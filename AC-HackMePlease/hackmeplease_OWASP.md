# Мапінг вразливостей CTF на **OWASP Top 10 (2021)**

---

## A01 – Broken Access Control

### Прояв у CTF:

1. Директорія конфігурації доступна напряму:

```
http://192.168.56.107/seeddms51x/conf/
```

2. Конфігураційний файл доступний без авторизації:

```
settings.xml
```

3. Завантажені файли доступні напряму через web-root:

```
/seeddms51x/data/1048576/<document_id>/1.php
```

---

### Чому це Broken Access Control:

* Відсутні обмеження доступу до:

  * системних директорій;
  * конфігураційних файлів;
  * внутрішнього сховища файлів.
* Будь-хто може читати або виконувати внутрішні ресурси без автентифікації.

---

### Наслідки:

* Витік паролів БД;
* Можливість виконання довільного коду;
* Повний компроміс сервера.

---

---

## A02 – Cryptographic Failures

### Прояв у CTF:

1. Паролі зберігаються як **MD5-хеші**:

```
f9ef2c539bad8a6d2f3432b6d49ab51a
```

2. Відсутній:

* salt;
* adaptive hashing (bcrypt / argon2).

---

### Чому це Cryptographic Failure:

* MD5 давно вважається криптографічно небезпечним.
* Можливий brute-force, rainbow tables, підміна хешів.

---

### Наслідки:

* Компрометація облікових записів;
* Підміна автентифікації;
* Несанкціонований доступ адміністратора.

---

---

## A03 – Injection

### Прояв у CTF:

1. Повний доступ до MySQL без обмежень:

```bash
mysql -u seeddms -p seeddms -h 192.168.56.107
```

2. Можливість виконання довільних SQL-запитів:

```sql
UPDATE tblUsers SET pwd='...' WHERE login='admin';
```

---

### Чому це Injection:

* Неконтрольований доступ до БД дозволяє:

  * змінювати дані;
  * підміняти автентифікацію;
  * порушувати цілісність.

> Навіть якщо це не класична SQL-інʼєкція через веб-форму — це все одно **інʼєкційний контроль доступу на рівні даних.**

---

### 💥 Наслідки:

* Підміна облікових даних;
* Повний контроль над додатком;
* Компрометація даних.

---

---

## 🔴 A05 – Security Misconfiguration

### ✅ Прояв у CTF:

1. Відкриті службові директорії:

```
/conf/
/data/
```

2. MySQL доступний з мережі без firewall.

3. Відсутні:

* обмеження доступу до конфігів;
* заборона виконання PHP у data-каталозі;
* hardening вебсервера.

---

### Чому це Security Misconfiguration:

* Система розгорнута з небезпечними дефолтними налаштуваннями.
* Відсутній мінімальний hardening.

---

### Наслідки:

* Масштабна поверхня атаки;
* Легке зловживання конфігураційними помилками.

---

---

## A07 – Identification and Authentication Failures

### Прояв у CTF:

1. Стандартні облікові дані (спроби):

```
admin:admin
admin:password
```

2. Можливість прямої підміни пароля через БД.

3. Відсутність:

* захисту від brute-force;
* контролю цілісності акаунтів.

---

### Чому це Authentication Failure:

* Слабкий контроль автентифікації.
* Відсутність механізмів захисту облікових записів.

---

### Наслідки:

* Захоплення адмін-доступу;
* Повна компрометація системи.

---

---

## A08 – Software and Data Integrity Failures

### Прояв у CTF:

1. Можливість завантаження виконуваних файлів (`.php`).

2. Відсутня:

* валідація типів файлів;
* перевірка контенту;
* контроль цілісності.

---

### Чому це Integrity Failure:

* Додаток довіряє завантаженому контенту.
* Відсутній контроль ланцюга довіри.

---

### Наслідки:

* Завантаження шкідливого коду;
* Remote Code Execution.

---

---

## A10 – Server-Side Request Forgery (частково)

⚠️ У цьому CTF прямо не використовується, але:

SeedDMS має функціонал роботи з зовнішніми ресурсами (індексація, preview, plugins).
За відсутності контролю — потенційно можливий SSRF.

Можна згадати як **потенційний ризик**, але не як фактичну вразливість.
